# Q: Для чого ускладнювати оплати і як виконати оплату, коли є мінус по відвідуванням та клієнт закриває його разовими відвідуваннями?

## Answer

Expanded from original query via graph vocab: [negative, closure, visit, visits, payment, one, membership, мінус, разові, оплата]. The current application has no completed workflow for closing a negative membership balance with one-off payments. Standalone CreatePayment explicitly rejects NegativeClosure and ordinary OneOff payments do not recalculate Membership state. IssueMembership preview exposes CoverWithNewMembership and RecordExplicitClosure as unavailable/deferred; only LeaveVisible is accepted. Therefore the user cannot complete this correctly in the current UI. A safe future reception action should atomically record the cash Payment, explicit negative-closure source fact for the selected Membership and visit count, recalculate the Membership, and append audit. Until implemented, an ordinary OneOff payment can only record cash with a comment; the negative remains visible and this is not a real closure.
